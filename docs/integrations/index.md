# Integration Guides

PolePosition keeps external-system scaffolds opt-in. A new project starts lean,
then you add integration helpers only when the application needs them.

Current integration surfaces. Each adds settings, an env entry, a dependency,
and a test double unless noted:

| Integration | What it scaffolds | Guide | Example |
| --- | --- | --- | --- |
| Kafka | Event-streaming producer and consumer helper | [Kafka](kafka.md) | [Quick Start](../examples/kafka-quick-start.md) |
| RabbitMQ | AMQP publisher, consumer helper, queue factory | [RabbitMQ](rabbitmq.md) | [Quick Start](../examples/rabbitmq-quick-start.md) |
| Redis | Async cache helper | [Redis](redis.md) | [Redis Cache](../examples/redis-cache.md) |
| RQ | Redis-backed background job queue helpers, worker factory | [RQ](rq.md) | — |
| LLM | Provider-agnostic adapter stubs (generated by an `ai-prompt` module) | [LLM](llm.md) | [OpenAI Prompt](../examples/openai-prompt.md) |

Integration scaffolds are starting points. They do not start background
consumer loops inside the FastAPI application process. Keep long-running
workers explicit in your deployment or runtime code.

For end-to-end examples, see:

- [Kafka Quick Start](../examples/kafka-quick-start.md)
- [RabbitMQ Quick Start](../examples/rabbitmq-quick-start.md)
- [Redis Cache](../examples/redis-cache.md)
- [OpenAI Prompt](../examples/openai-prompt.md)

After adding an integration, run:

```bash
polepos check
uv sync --extra dev
```
